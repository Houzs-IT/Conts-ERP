# 财务第 1.5 期：顾客和供应商名单、装修合约整笔入账、项目状态表 — 设计

- 日期：2026-10-23
- 依据：财务 SOP（`docs/finance/FINANCE-SOP.md`）2.1、4.2.1、4.2.3，财务（chew）2026-10-22 / 23 确认
- 前提：第 1 期（`2026-10-20-finance-phase1-ledger-design.md`）已上线；正式环境开账日期还没设，所以这些改动上线时不会影响已经入的账

---

## 1. 要解决什么

| 财务要的 | ERP 现在 |
|---|---|
| 每个顾客一笔资料（debtor），挂在一个 control 下面，财务可以维护 | 没有顾客名单可以挂 control；订单上的 debtor 代码是自由输入的文字；装修合约根本没有代码 |
| 新订单的新顾客自动开 debtor、自动编码 | 不会开，也不会编码 |
| 每个顾客、供应商的明细账 | 没有画面（分录上有记顾客代码，资料在） |
| 装修合约成立就整笔入账，发票不入账，收钱贷 debtor | 每开一期发票才入账（借应收、贷装修科目） |
| 每个项目一个预收款子户口 | 没有 |
| 项目状态表 | 没有 |
| 导入 AutoCount 科目表 | 导入程序读错栏位（名称、银行标记会丢）；客户、供应商户口会变成科目，应收、应付变成父科目后不能入账 |

## 2. 顾客（Debtor）和供应商（Creditor）

### 2.1 顾客名单（新表 `scm.debtors`）

一个顾客一笔：代码、名称、control 科目、电话、电邮、地址、备注、停用；可以连到订单上的顾客（`scm.customers`）。

- **代码**：control 前三码 + 字母 + 流水号，例 `301-M155`。
  - 字母：名称去掉称谓后的第一个英文字母；MR、MS、MRS、MDM、MISS、DR 开头的个人一律用 `M`（照 AutoCount 现有的做法）。名称第一个字是数字时用 `0`。
  - 流水号：同一个「前三码 + 字母」现有最大的号码 + 1，至少三位，不限位数（M999 之后是 M1000）。
  - 代码开了就不改；名称可以改。
- **维护画面**：Finance > Debtors。按 control 分组显示（像 AutoCount「某 control 下面的顾客」），可以新增、修改、停用、搜寻。要会计权限。
- **自动开**：新订单的顾客在名单里找不到时（同名同电话），自动开一个 debtor，挂在这张单对应的 control 下面（见 2.3），订单和之后的发票、收款都带这个代码。

### 2.2 供应商

供应商名单（`scm.suppliers`）已经有，也已经有代码。加两样：
- **control 科目**栏：没有填的照现在的规则（代码 405- 开头的记 405-0000，其他记 400-0000）。
- **新供应商自动编码**：照顾客同样的规则，例 `400-H011`。手动输入代码的照旧可以。

### 2.3 什么单挂哪个 control

由财务在设定里维护一张对照表：

| 单的类型 | 默认 control |
|---|---|
| 装修合约 | 301-0000 RENOVATION CUSTOMER |
| 自家装修合约 | 302-0000 INHOUSE RENOVATION CUSTOMER |
| 一般销售订单（家具等） | 待财务定 |
| Rental | 303-0000 RENTAL CUSTOMER（新开） |

- **装修和自家装修怎么分：待财务定**（SOP 第 12 节）。ERP 现在没有这个标记。定了之前，装修合约一律挂 301-0000，财务可以在顾客资料里改 control。
- Rental 的订房和收款在 Property OS，不在这个记账系统，所以 303 的顾客这一期不会自动开，只用在期初余额和手动的分录。

### 2.4 记账按顾客自己的 control

所有借贷应收的分录（发票、退款单、收款、订金、转单、退款），应收那一行改记**这个顾客的 control**，并注明顾客代码。供应商同理（应付那一行记供应商的 control）。

跟着要改的检查：
- 手动分录不能动的科目，从「应收、应付两个规则」扩大到「所有 control 科目」（科目表特殊类型 SDC / SCC 的都算）。
- 「控制科目核对」、期初核对：每个 control 各算一行。
- 每个 control 科目底下不能再有子科目（不然不能入账）；会计设定页照样会标红。

### 2.5 明细账

Finance 里新增「Debtor ledger」和「Creditor ledger」：选一个顾客（或供应商）和日期，列出所有往来（合约、发票、退款、收款、订金），每行有余额，期初余额在最上面。资料来自总账分录上的顾客代码。

## 3. 科目表导入

- 导入程序按表头找栏位（`Acc. No.`、`Description`、`Special Acc Type`），AutoCount 新旧两种格式都认得。
- 特殊类型 `SDR`（顾客）、`SCR`（供应商）的户口**不当作科目**：
  - SDR → 导入顾客名单，control = 它上面那个科目（例 301-M001 → 301-0000）；
  - SCR → 导入供应商名单，control = 它上面那个科目。
- 预览画面分开显示「科目 N 个、顾客 N 个、供应商 N 个」，确认后才导入。
- 一次上限从 1,000 提高（Conts 的表有 889 行，以后会更多）。
- **ERP 现有的 7 个供应商**（HOOKKA、DHI 等）的代码跟 AutoCount 的（400-H006 等）不一样：导入时按名称配对，配对到的改成 AutoCount 的代码，让财务在预览确认（**待财务确认这个做法**）。
- 导入后另外加 303-0000 RENTAL CUSTOMER。

## 4. 装修合约整笔入账

例：MS LEE（301-M155），合约 RM 30,000，品牌 The Conts，项目 SKYLINE A-12-06。

| 动作 | 什么时候 | 入账 |
|---|---|---|
| 合约成立 | 报价单转成合约 | 系统先开项目的预收款子户口（481-S018 SKYLINE A-12-06），再入：借 301-0000（MS LEE）30,000 / 贷 481-S018 30,000 |
| VO 批准 | 合约金额改变时 | 借或贷差额（同样两个科目） |
| 合约取消 | 取消时 | 冲销上面所有分录 |
| 开发票 | 每期 | **不入账**（只是单据，照旧有发票号、到期日、寄给顾客） |
| 负数的一期（退款单） | 改单少了钱 | **不入账**（差额在 VO 那一笔已经记了） |
| 顾客付钱 | 收款时 | 借 银行 / 贷 301-0000（MS LEE），注明付哪张发票 |
| 转收入 | 每月底 | 借 481-S018 / 贷 装修收入，按完工进度（见下） |

- **预收款总户口按品牌**：Dreamcrafter → 480-0000，The Conts → 481-0000（财务在设定里维护）。子户口代码照顾客的规则（总户口前三码 + 项目名称第一个字母 + 流水号）。
- **项目名称**：用项目的大楼和单位（例 SKYLINE A-12-06），财务可以改。
- **转收入**：SOP 4.2.1 要系统每月底按「已记账成本 ÷ 预计总成本」自动转。这一期**先由财务每月做一笔分录**（项目状态表会算好每个项目这个月要转多少，照着做）；系统自动转放在下一期，因为要先有「预计总成本」的维护和 VO、超支的提醒。
- **开账前就签的合约**：它们的预收款在 AutoCount 已经有子户口（例 481-S012），导入科目表后会在 ERP 里。开账前要把这些项目连到它们的子户口（会计设定页加一个对照），开账后的 VO 和转收入才会记到对的地方。
- **订单上的成本**：PO 拆单、工地收货照旧；供应商发票照旧记装修成本 / 应付。

## 5. 项目状态表

Finance 里新增「Project status」：每个装修项目一行，栏位选择器（跟销售订单列表一样），财务可以挑栏位、排顺序、存成默认。

| 类别 | 栏位 | 来源 |
|---|---|---|
| 项目 | 项目、顾客代码和名称、销售员、品牌、类型、目前阶段、预计交房日、延误 | 项目和合约 |
| 金额 | 合约金额、VO、合约总额 | 合约（原始金额、VO 净额） |
| 收钱 | 已收、Outstanding、收钱 %、下一期（哪一期、金额、何时该开） | 发票、收款、分期 |
| 收钱 gap | 第 1→2、2→3、3→4 期隔几天，按收钱日期一套、按开发票日期一套 | 收款日期、发票日期 |
| 收入 | 已转 Sales、还没转、完工 %、本月该转 | 预收款子户口余额；完工 % = Cost spent ÷ 预计总成本 |
| 开销 | 预计总成本、Cost spent、已下单还没记成本、预计还要花、欠供应商；超支标红 | 订单每行的成本；供应商发票（经采购单连到项目）；采购单还没开发票的部分 |
| 毛利 | 预计 GP%、到目前为止 GP% | 上面的数字 |
| 提醒 | 完工 % 比收钱 % 高很多就标红 | 上面的数字 |

- **预计总成本**：这一期 = 订单每一行的成本合计（VO 会跟着变）。SOP 说超支时由 HOD 和财务更新预计，这个维护放在下一期，跟自动转收入一起做。
- **项目额度（SOP 3.4，70%）**：ERP 还没有这个功能，这一期先不放这一栏；做了额度功能再加。
